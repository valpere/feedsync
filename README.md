# feedsync

Supplier price feeds in, marketplace price lists out — with a hard guarantee
that what you publish is valid.

`feedsync` reads a supplier feed (YML/XML, CSV or JSON), applies category
mapping, currency conversion, markup rules and stock filtering, writes
**Rozetka** and **Prom.ua** price lists, and optionally syncs price and stock
into an OpenCart-style product table.

## The actual hard problem

Converting XML is easy. The hard part is that a marketplace rejects or
silently drops an entire price list because of a few bad offers, and feeds are
big enough that you cannot eyeball them. So:

- **Streaming.** The feed is read token by token and each `<offer>` is decoded
  on its own. Memory does not grow with feed size.
- **Validate before publishing, independently.** After a target file is
  written to a temp path it is re-read from disk and checked by the same rule
  set, not by trusting the writer. Only then is it atomically renamed over the
  live file. A failed run leaves the previous file in place.
- **Reject per offer, with reasons.** A bad offer is dropped and listed in
  `report.json` with the rule it broke; it never poisons the file.
- **Stable IDs.** Offer IDs are kept if they are already `[A-Za-z0-9]+`,
  otherwise derived deterministically (`prefix` + SHA-1 hex), so the same
  supplier SKU gets the same ID on every run.
- **Money is integer kopecks**, never floats.
- **Out-of-stock is not just "missing".** Zero-stock items are removed from the
  price lists *and* zeroed in the CMS (price left untouched), otherwise the shop
  keeps selling what the supplier no longer has.

## Usage

```bash
make build
make gen-sample                    # 25,000-offer sample supplier feed
./bin/feedsync convert -c examples/config.yaml
./bin/feedsync validate -target rozetka out/rozetka.xml
```

```
feedsync convert  -c config.yaml [-every 30m] [-opencart-dsn DSN]
feedsync validate -target rozetka|prom FILE
feedsync gen-sample -n 25000 [-seed 1] -o supplier.yml
feedsync opencart-seed -dsn DSN -n 25000 [-prefix oc_]
```

`-every` keeps the process running and repeats the conversion on an interval
(a failed run is logged and the previous files are kept). DSN is a MySQL DSN or
`sqlite:PATH`.

### OpenCart sync

```bash
make mysql-up mysql-seed           # MySQL 8.4 in Docker, port 3307
make mysql-sync                    # convert + sync price/stock
make mysql-down
```

Updates are batched `UPDATE … CASE` statements inside one transaction, matched
on `oc_product.model` = supplier SKU. Only rows whose values actually differ are
touched, so a repeat run is a no-op.

### Configuration

See [`examples/config.yaml`](examples/config.yaml): source, category map,
currency rates, first-match-wins markup rules (percent/fixed, by price range or
category, with round-up), stock filter, picture rules, targets.

## Verification

Measured on the 25,000-offer sample feed generated by `gen-sample` (26 MB), 16-core machine,
Go 1.26, MySQL 8.4 in Docker:

| Measure | Result |
|---|---|
| Convert 25,000 offers → Rozetka + Prom | ≈1.5 s wall, ≈36 MB peak RSS |
| Convert 100,000 offers (105 MB) | ≈6.3–7.2 s wall, ≈91 MB peak RSS |
| Published files re-validated | 0 errors (both targets) |
| Rejected offers | 259 for Rozetka (missing/non-HTTPS pictures, missing vendor), listed with reasons in `report.json` |
| Dropped before export | 3,675 zero stock, 125 unmapped category, 61 unknown currency |
| OpenCart sync, first run | 19,119 rows updated in 39 batches, ≈0.7 s |
| OpenCart sync, repeat run | 0 updated, ≈25 ms |

Memory grows sub-linearly with feed size (4× the offers, ≈2.5× the RSS), which
is what streaming should look like.

`make test` runs the unit and integration tests with `-race` (the OpenCart
sync is tested against SQLite; the numbers above were taken on real MySQL).

## Connecting it to your shop

- **Supplier feed:** set `source.path` to the supplier's file or URL and pick
  `source.format` (`yml`, `csv`, `json`). A new format is one more reader in
  `internal/source` that calls the same `Handler` for each product.
- **Marketplaces:** each entry under `targets` writes one price list
  (`rozetka`, `prom`); point `out` at the directory your web server exposes and
  give the marketplace that URL.
- **CMS:** put the MySQL connection string in `opencart.dsn` (or pass
  `-opencart-dsn`), set `opencart.prefix`, and price/stock sync starts with the
  next run; SQLite works the same way for a local copy.
- **Schedule:** `feedsync convert -c config.yaml -every 30m` keeps the files
  and the shop current; the report JSON shows every rejected offer and why.
- **Your rules:** category map, currency rates, markup rules and picture rules
  live in the config file.

## Layout

```
cmd/feedsync            CLI
internal/source         YML / CSV / JSON streaming readers
internal/transform      category map, currency, markup, IDs, drop reasons
internal/export         Rozetka and Prom.ua XML writers
internal/validate       rule set (offer-level and whole-file)
internal/pipeline       single pass, temp file, validate, atomic publish, report
internal/opencart       batched price/stock sync, schema, seed
internal/samplegen      deterministic sample supplier feed
```

## Stack

Go, `encoding/xml` streaming, `modernc.org/sqlite` (tests), MySQL 8.4,
`gopkg.in/yaml.v3`, Docker.
